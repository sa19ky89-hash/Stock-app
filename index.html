System Architecture & Overview

このプログラムは何をしているのか？

指定した企業の株価データを自動取得し、6つの説明変数（テクニカル指標）を元に機械学習（LightGBM）で翌日の価格変動パターンを学習。さらに過去の予測誤差を用いたモンテカルロ・シミュレーションとSHAP要因分析により、今後1ヶ月の株価推移を「ブレ幅（90%信頼区間）」および「上昇・下落の要因（プラス・マイナス方向性）」付きで可視化するWebアプリです。

データ自動取得

yfinanceで日米銘柄・指数データをリアルタイム連携

時系列AI学習

LightGBM×時系列CVで未来漏洩（リーク）を完全防止

確率的シミュレーション

300回の試行でリスク範囲（信頼区間）を定量化

SHAP要因・方向性分析

各指標がプラス/マイナスどちらに効いているかを可視化

Feature Engineering & Input Variables

2. モデルの説明変数（入力指標）とその役割・意味

機械学習モデル（LightGBM）が「明日株価が上がるか下がるか」を予測するための判断材料として、以下の**6つの説明変数（`FEATURES`）**を日々のデータから計算して入力しています。

Close 価格基本指標

終値（当日の最終株価）

その日の取引の最後に成立した株価。市場参加者全体の最終的な合意価格であり、移動平均やリターン計算の基礎となる最も重要な原データです。

AIでの役割: 株価の現在の絶対水準や、移動平均線（SMA_20）との乖離率を判定する基準となる。
Volume 市場のエネルギー

出来高（売買成立株数）

一日に売買が成立した株式の総数。「相場のエネルギー」を表し、出来高の急増は市場の関心の高まりやトレンド転換の強力なサインとなります。

AIでの役割: 「価格変動に伴う出来高の増加」を検知し、ダマシのない本物のトレンドかを識別する。
SMA_20 トレンド指標

20日単純移動平均線

直近20営業日（約1か月間）の終値の平均値。日々の細かなノイズを除去し、短期〜中期のトレンドの方向性をクリアに示します。

AIでの役割: 株価が平均線より上か下か、押し目買い・戻り売りのサポート線として効いているかを学習。
RSI (14日) オシレーター指標

RSI（相対力指数）

過去14日間の値上がり幅と値下がり幅の割合から、売買の過熱感を0〜100%の数値で表します。一般に70%以上は「買われすぎ」、30%以下は「売られすぎ」と判断されます。

AIでの役割: 相場の過熱（買われすぎ・売られすぎ）に伴う自律反発・反落のリバウンド局面を捉える。
MACD モメンタム指標

MACD（移動平均収束拡散）

2つの指数平滑移動平均（EMA：短期12日・長期26日）の差から算出した指標。トレンドの発生や転換のタイミング（ゴールデンクロス・デッドクロス）を捉えます。

AIでの役割: 新しい上昇・下落トレンドが始まったばかりの勢い（モーメンタム）を判断する。
Return 日次変化率

前日比リターン（株価騰落率）

前日終値からの価格の変化率（例: `+1.5%` や `-0.8%`）。株価そのものは銘柄によって数千円〜数万円とバラツキますが、率（%）に直すことで統計的な比較・学習が容易になります。

AIでの役割: 直近1日の値動きの勢いや、連続で上げている・下げているといった短期モメンタムを学習。
🎯 目的変数（予測ターゲット）：Target_Return

モデルは上記6つの説明変数（本日の状況）から、正解データである「翌日の前日比リターン（Target_Return）」を予測するように学習します。株価の「金額そのもの」ではなく「変化率（％）」を予測対象にすることで、モデルの安定性を確保しています。

X: FEATURES ➔ y: Target_Return
Validation Strategy & Split Selection

3. 時系列クロスバリデーション（TSCV）と分割数（n_splits）の考え方

なぜ通常のK-Foldではなく「時系列分割（TSCV）」なのか？

通常のK-Foldクロスバリデーションはデータをランダムにシャッフルするため、「2024年のデータで学習して2023年を予測する」といった「未来のデータ漏洩（データリーク）」が発生してしまいます。これでは検証時の精度は異常に高く見えても、実際の未来予測では全く使い物になりません。

時系列分割（Expanding Window）の原則

「過去のデータだけで学習 ➔ その直後の未来データで検証」という時間の順序（時間軸の矢印）を厳密に守りながら検証を繰り返します。本番と同じ評価基準を再現できる唯一の方法です。

分割数（n_splits）は多ければ多いほど良いのか？

結論から言うと、「単に分割数を増やせば良いというわけではありません」。 分割数を増やしすぎると、1つ目のFold（Fold 1）における初期の学習データ期間が極端に短くなり、モデルが正常に学習できずに異常な誤差が生じるリスクがあります。

分割数が多すぎる場合のデメリット
  • Fold 1 の学習データ不足による精度過小評価と異常残差の混入
  • 検証期間が短くなりすぎ、一時的なニュース等ノイズの影響を受けやすくなる

データ取得期間に応じた最適分割数（n_splits）の推奨基準

データ取得期間 サンプル数（約） 推奨分割数 (`n_splits`) 特記事項・理由
1年 (1y) 約250営業日 3 〜 5 分割 (初期値: 5) 初期Foldでも数か月分の学習データを確保可能。最もバランスが良い。
2年 (2y) 約500営業日 5 〜 7 分割 データ量に余裕が出るため、分割数をやや増やして残差サンプル数を増加させても安全。
5年 (5y) 約1250営業日 5 〜 10 分割 十分なデータ量。ただしあまり古い相場環境が直近の検証を阻害しないよう注意。
Probabilistic Forecasting & Sample Size

4. モンテカルロ・シミュレーションと試行回数の妥当性

「残差ブートストラップ」による再帰予測メカニズム

AIが予測する単一の株価（点予測）は平均的なものに過ぎません。本アプリでは、時系列CVで蓄積した「過去の予測誤差（残差プール）」からランダムに1つ誤差を抽出し、AIの予測リターンに加算しながら20営業日先まで1日ずつ再帰予測します。

【t日目 ➔ t+1日目の計算式】
調整後リターン = AI予測リターン + ランダム抽出(残差プール)
翌日予想株価 = 本日株価 × (1 + 調整後リターン)

試行回数（n_simulations）は「300〜500回」がなぜ妥当か？

統計学における「大数の法則」により、シミュレーションの推定誤差（標準誤差）は試行回数 $N$ の平方根（$\sqrt{N}$）に反比例して減少します。300〜500回に達すると確率分布（信頼区間の帯）が十分に収束し、それ以上増やしてもグラフの形や結論はほとんど変化しなくなります。

100 回試行 高速 / 軽量

推定誤差: $\approx 10\%$ ($\frac{1}{\sqrt{100}}$)

計算時間は一瞬（1秒未満）ですが、上位5%や下位5%などの信頼区間の端（外れ値側）が実行のたびにややカクつき、安定性に欠けます。

アプリ初期設定（推奨）
300 〜 500 回試行 ベストバランス

推定誤差: $\approx 4.5\sim 5.7\%$ ($\frac{1}{\sqrt{300\sim 500}}$)

画面のレスポンス（1〜3秒程度の待ち時間）を損なわず、90%信頼区間の帯も非常に滑らかに収束します。Webアプリとして最も理想的な設定です。

10,000 回試行 機関投資家レベル

推定誤差: $< 1\%$ ($\frac{1}{\sqrt{10000}}$)

極めて精密な分布が得られますが、200,000回（$10,000 \times 20\text{営業日}$）のテクニカル指標再計算ループが発生し、Web処理が重くなります。

5. 特徴量重要度（Gain）と SHAP分析（方向性）の違い

① 重要度スコア（Gain） ➔ 「影響の大きさ」

LightGBMが予測の分岐を作成する際、どの指標が一番「エラー（誤差）削減に貢献したか」を表す指標です。

【メリットと限界】

〇「AIが何を一番頼りにしているか」が一目でわかる。

✕「上がると予測しているのか、下がると予測しているのか（プラス/マイナス）」の方向性は判別できない。

② SHAP分析（Summary Plot） ➔ 「方向性と影響」

各データポイントが株価予測を上げる（＋）方向、下げる（−）方向のどちらにどれくらい引っ張ったかを厳密に計算します。

【グラフの読み解きルール】

・右側（プラス領域）：株価上昇の予測に寄与

・左側（マイナス領域）：株価下落の予測に寄与

・赤色(High)：指標が高い時 / 青色(Low)：指標が低い時

読み解き例：銘柄ごとのAIの思考回路が判明する

例えば **「RSI (相対力指数)」** の行で、赤色のドット（RSIが高い状態）が左側（マイナス領域）に固まっていた場合：
➔ AIは「この銘柄はRSIが高くなると（買われすぎると）、過熱感から**翌日の株価が下がる可能性が高い**」と評価していることが分かります。

Core Machine Learning Engine

6. LightGBM（機械学習モデル）の仕組み

勾配ブースティング決定木

LightGBMは、浅い条件分岐の木を100本作成し、直前の木が犯したエラー（残差）を次の木が補正するように順番に学習していくアルゴリズムです。

重回帰分析との違い

重回帰分析のような直線的（比例）ルールではなく、「RSI>70 かつ MACDが下降」といった非線形で複雑な相関ルールを自動で学習できます。

予測対象（目的変数）

株価そのものではなく、より定常性（統計的安定性）が高い「翌日の価格変化率（`Target_Return`）」を予測対象としています。
